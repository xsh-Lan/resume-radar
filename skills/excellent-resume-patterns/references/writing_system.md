# 从事实到句子

## 先重建经历，再选择句式

以经历为单位找到主叙事：服务对象与痛点 → 本人任务 → 行动与取舍 → 产出或结果。STAR中的背景与任务只保留理解动作所需的部分，核心是行动和结果。一个经历可用数条分别承接调研、方案、验证，不应把全部环节塞进每句。

默认表达为“【具体主题】问题或任务；本人动作与关键方法；已知交付或结果”。也可用CAR省略独立任务说明；结果可靠且最有辨识度时用XYZ把结果前置。没有结果就止于交付和阶段，没有选择依据就不编造取舍。标题概括具体工作，而不是“项目背景”“能力提升”。

虚构示例只示范方法：已知访谈8名商家、发现优惠配置入口难找、画原型提交评审、尚未上线。可写“【优惠入口调整】访谈8名商家，识别优惠配置入口难找的问题；整理问题清单并绘制调整原型，提交负责人评审。”不能写“优化转化率”或“推动上线”。原因应说明：用户问题与原型形成对应，访谈数量是研究范围，交付阶段是评审，不是已验证效果。

结果分层：任务量说明接触规模；产物说明做出了什么；采用或上线说明落地阶段；用户或业务变化需要测量与归因。优先展示当前材料实际能证明的最高一层，同时保留支撑它的关键方法。参考卡片提供判断条件，不替用户提供事实。

先选目标岗位下最有力的事实，再安排顺序。结构按用户目标和材料调整，原始事实档案保留。每段围绕能支撑岗位要求的少量主题，条数服从材料和版面。

句式由事实条件决定：

| 已有事实 | 可用结构 | 仍须确认 |
|---|---|---|
| 对象、调研动作、发现 | 研究对象 → 个人动作 → 发现/交付 | 方法和发现的依据 |
| 备选方案、约束、决策 | 约束 → 比较与选择 → 已知结果 | 谁作出决定、结果状态 |
| 个人交付、项目阶段 | 具体产物 → 任务范围 → 当前阶段 | 采用和上线效果 |
| 基线、结果、口径与归因 | 动作 → 可归因的指标变化 → 边界 | 数据来源与时间范围 |
| 参与或协助 | 本人承担的部分 → 与团队交付关系 | 不将团队全量结果归为个人 |

原有24句型改为 `reference_cards.json` 的事实条件，不再默认套用“主导、0到1、闭环、显著提升”。详尽、技术术语和数字数量都不是充分的质量标准。
