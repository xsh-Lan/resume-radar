# 岗位与证据分析

读取插件根目录的 `standards/diagnosis.md`，导出文件时使用 `standards/data-contract.md`。已有事实与来源直接复用，模块之间按 ID 交接；使用本插件资源。

1. 确认任务范围、输入模式、用户目标、职级和场景。只分析用户 JD 时无需全文编辑；方向或探索的完整评估按 `skills/resume-radar/references/job-discovery.md` 检索真实 JD。直接调用本模块也保留这条检索路径，用户仅要求概念性岗位解释时可不检索。JD 模式逐项保存原文；方向模式区分样本要求与模型假设。
2. 将核心要求解释成工作任务、交付责任、决策要求与协作范围。分别标识明示硬条件、普通要求、加分项和解释性假设。用岗位任务解释为何重要。
3. 对每个要求，引用候选人原文及用户补充。区分参与执行、独立产出、方案取舍、结果责任。说明现有证据能证明到哪一层，不以技术关键词代替判断。
4. 形成 direct/transferable/partial/unknown/missing/conflicting 的支持状态，按诊断标准区分差距。材料未写先追问；硬条件不符不能被语言或版式优点抵消。
5. 给出有完整推导的诊断、最可能改变判断的追问和相应行动。同一根因复用已有诊断 ID；按事实对象、原因和解决动作建立稳定 issue_key，关联多条要求与证据，标 priority=high/medium/low。原文清楚支持的优势也要说明。默认不计算综合百分制分数。

## 整体匹配结论

整体判断必须直接回答“以当前简历能否支撑申请这个职级与任务类型”，不能用经历概括或建议列表代替结论。先检查资格硬条件，再判断核心任务支持程度，最后给投递行动：具备申请基础、补强关键材料后申请、当前不适配或信息不足。给明确理由，不预测面试率。

用3–5项最能改变岗位判断的要求对照，标明基本达标、部分达标、尚不能判断或不符合；每项关联真实要求与候选人证据。基本达标指材料支持该职级的任务基础，不代表熟练或强于其他候选人；部分达标指已有相关动作但关键深度或结果不足；未知不能当不符合，明确硬条件冲突不能被优势抵消。参与执行对于实习岗可以达标，不把独立负责完整业务当作统一实习门槛。

综合时按核心任务的重要性与硬条件判断，不数达标项、不算平均分。写清最强依据和最影响匹配的短板，区分简历没讲清与经历确实缺少。方向探索只能对已读取样本代表的任务作暂定判断；历史、相邻岗位与转录须标明，不扩展成整个行业或所有公司的标准。不同方向分别判断，不能混合要求后给一个总评。资格、到岗时间和每周出勤单独说明是否已确认。

交付：requirements、evidence、diagnoses、必要的 role_options 和 followup questions。每条关键诊断指向来源位置与要求，写清目前支持和不支持的判断。改写由 resume-refiner 依据诊断完成。

用户明确要求评分时，先读 `standards/scoring.md`，说明用途、依据、缺失项及局限；没有可靠校准时优先给分项支持情况，不输出假精确概率。
