# 岗位与证据分析

读取插件根目录的 `standards/diagnosis.md`，导出文件时使用 `standards/data-contract.md`。已有事实与来源直接复用，模块之间按 ID 交接；使用本插件资源。

1. 确认输入模式、用户目标、职级和场景。JD 模式逐项保存原文；方向模式明确标准依据；探索模式依据实际任务和偏好比较有材料支持的方向。
2. 将核心要求解释成工作任务、交付责任、决策要求与协作范围。分别标识明示硬条件、普通要求、加分项和解释性假设。用岗位任务解释为何重要。
3. 对每个要求，引用候选人原文及用户补充。区分参与执行、独立产出、方案取舍、结果责任。说明现有证据能证明到哪一层，不以技术关键词代替判断。
4. 形成 direct/transferable/partial/unknown/missing/conflicting 的支持状态，按诊断标准区分差距。材料未写先追问；硬条件不符不能被语言或版式优点抵消。
5. 给出有完整推导的诊断、最可能改变判断的追问和相应行动。原文清楚支持的优势也要说明。默认不计算综合百分制分数。

交付：requirements、evidence、diagnoses、必要的 role_options 和 followup questions。每条关键诊断指向来源位置与要求，写清目前支持和不支持的判断。改写由 resume-refiner 依据诊断完成。

用户明确要求评分时，先读 `standards/scoring.md`，说明用途、依据、缺失项及局限；没有可靠校准时优先给分项支持情况，不输出假精确概率。
