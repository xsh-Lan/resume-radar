# 一个决策：本次求职目标

完整任务只保留一个用户决策，将求职方向、JD来源、目标岗位合并在当前 Codex 对话中完成。用户选定或委托后直接分析，最后打开原件对照报告。默认检查全份简历、逐句审阅并生成忠实优化全文，未知事实直接标注；不设置分析范围、输出开关、方案确认或事实追问关卡。

用户主动提出的局部修改、指定范围或面试训练按原请求处理，不强制转成完整任务；三个专业模块继续独立可用。

## 准备目标选项

先读取简历和用户已有指令/JD。已明确说明分析对象的指令就算本次目标决策，直接沿用。只缺必要材料时获取材料，不重新询问已确定的偏好。用 workflow.py init --resume <PDF> --run-dir <新目录> --candidate-key <键> --guided 初始化，提供JD时加 --jd <JD.txt>。ROOT 是同时含 scripts、skills、standards 的安装根目录，个人资料保存在用户工作区。

尚无明确目标时，使用宿主提问工具提出一次合并问题“这次按什么目标诊断简历？”，选项按材料调整，第一项始终保留“不明确，帮我推荐”：

1. 不明确，帮我探索并推荐一个适合的岗位：委托 Agent 根据简历检索真实JD并选择主目标，说明推荐理由，随后直接分析。
2. 按我指定的岗位/JD：在同一回答中提供岗位、已有JD或选定已展示的真实候选。
3. 通用简历诊断：不针对具体JD，直接分析经历结构、项目价值和表达。

如果已检索到候选，可把方向、公司、岗位和JD来源一起呈现，用户的一次选择同时确定三者；不先确认方向、再确认来源、再确认岗位。城市、职级等使用原有明确约束，缺少时按材料作可撤回的假设并披露，不新增偏好问卷。用户说“没有偏好”“你来推荐”视为委托，不把沉默或默认选中当同意。

## 确定真实分析对象

Route 01（provided）：使用用户实际提供的JD。Route 02（auto）：按 job-discovery.md 读取真实招聘正文、记录来源与状态，通过 add-jd 导入。用户委托时根据材料和JD任务关联选择主目标，不另问一轮确认；用户已选候选时直接使用。Route 03（none）：不检索岗位，不构造虚假招聘要求。

检索不充分时说明局限，优先完成有依据的条件诊断，不反复要求用户决策。委托自动选岗但最终没有可用JD时，记录降为通用诊断的原因并保持目标方向为暂定，不伪造匹配结论。目标确实发生变化时，只更新同一目标决策，不重新引入方案关卡。

## 保存唯一目标决策

将用户实际回答写 target-reply.txt。目标解析与实际选定对象写 target-values.json：

- target_choice：unclear/specified；保留原始方向是否明确。
- target：实际分析岗位名称；通用诊断可为空。
- jd_source：provided/auto/none，对应01/02/03。
- selected_jd_ids：实际导入的JD引用；通用诊断为空。
- delegated：布尔值，用户是否授权Agent推荐主目标。

```text
python <ROOT>/scripts/confirm.py --run-dir <目录> --target-record <目录>/target-values.json --response <目录>/target-reply.txt
python <ROOT>/scripts/confirm.py --run-dir <目录> --ready
```

这是一次目标记录，不要求 Stage 1、Stage 2、plan-prefill 或第二次用户回答。confirmation.json 的 kind=single_target，target_decision 保存目标，outputs 是程序固定输出，不是用户决策。

## 直接执行与交付

新运行 workflow_version=0.16。按route设置run.mode：01→jd、02→direction、03→general；target取本次确定对象。默认关注岗位任务与证据、项目价值、贡献边界、结果口径和表达结构。

分析中保留未知，不主动追问事实、不要求用户核实后才能继续。可交付保守改写，明确其与原始结果主张的差别。不要把材料未写判断为本人不会，不补数字、贡献或结果。逐句审阅覆盖完整原文，final_text生成忠实全文。通用诊断允许requirements为空、market_search=not_needed。

完成语义复核及机械校验后，render_report.py --open 打开报告。最终给主要诊断、报告及优化全文入口。用户可自主提出后续修改，报告复制、定位、处理标记均不是前置决策。

旧0.14/0.15运行继续兼容，已回答内容直接复用；新任务不再调用旧阶段确认或网页输入流程。
