# 岗位差距诊断标准 v2

## 推导链

每条重要诊断包含：岗位要求及依据 → 当前原文证据 → 已经证明的能力与责任范围 → 尚不能支持的判断 → 对该岗位的影响 → 验证问题或行动。表达为材料支持的判断，避免人格和能力的无依据评价。

岗位画像至少区分任务、交付责任、决策要求和协作范围。按职级确定深度。例如模型评测可以是执行既定测试、设计测试与归因、据此调整方案、建立上线门槛；这些是不同职责，不能仅凭术语出现视为等价，也不能要求所有实习者承担最终上线决策。

对每项核心要求检查：做过什么、本人负责什么、为何采用该方法、处理哪些约束、怎样理解结果。没有商业结果时，真实交付物、判断依据和项目阶段也能构成有效证据。

## 差距分类

| 类型 | 识别标准 | 行动 |
|---|---|---|
| expression | 已有事实充分，表达或组织不清 | 重写、重排、合并 |
| evidence_missing | 材料未呈现，尚不知道是否做过 | 追问、查已有材料 |
| experience_gap | 用户明确确认没有对应经历 | 补实践或调整投递范围 |
| depth_gap | 用户确认承担范围不足以支持目标责任 | 寻找更强事实、补职责实践 |
| transfer_gap | 已有类似能力，业务对象或约束不同 | 解释迁移依据及剩余未知 |
| hard_constraint | 明示条件与已提供事实不符 | 说明具体影响和选项 |
| source_conflict | 来源中的同一事实互相矛盾 | 展示冲突，请求确认 |

experience_gap 与 depth_gap 须有用户补充确认来源；未经确认，用 evidence_missing 或部分支持表达。证据未呈现不自动变为诚信风险。hard_constraint 必须指向 JD 明示硬条件，不能来自模式库或模型推测。

要求支持状态：direct、transferable、partial、unknown、missing、conflicting。missing 仅在已有明确反证或用户确认缺失时使用。状态描述支持情况，不是概率或最终录用判断。

## 关键追问

每个问题说明关联原句、影响哪项岗位判断以及希望补充的信息。先问能改变关键判断的问题，避免每句都机械追问数字。回答保存为新来源并更新相关证据与结论；跳过的事实继续标未知。

## 全文判断

先解释候选人的主线、最强证据、关键差距与取舍，再检查段落和句子。每句都要有处理状态，好句允许保留。合并和删除根据目标版本的信息价值判断；事实档案保留。完整审阅覆盖教育、经历、技能等所有实质单元，不要求对姓名或日期虚构能力诊断。

## 聚焦复核

检查原句是否存在、证据是否支持推断、要求是否真实、责任范围是否匹配、数字及状态是否保持、建议能否解决所述差距。不同模块意见冲突时回到对应来源和职责解决；不按票数更改分数。内容检查需要记录具体来源与发现，程序校验只证明可机械检查的部分。
