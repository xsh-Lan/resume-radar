# 运行架构

统一入口读取任务后选择局部编辑、单独岗位分析、面试训练、无 JD 探索或已有 JD 定制。按需读取专业模块的 SKILL，在当前助手中执行；不依赖未验证的子 Agent 注册机制。

所有模块共享 sources → evidence / requirements → diagnosis → sentence_review。诊断是问题根因的唯一记录，issue_key 去重，多个要求和编辑引用同一诊断；追问只更新受影响事实与结论。

无 JD 时宿主浏览工具读取真实招聘页面，add-jd 导入正文和元数据。requirements 的 sample_jd 引用招聘单元，候选人 evidence 只引用候选人来源。检索状态和样本不足显式保存；搜索结果摘要不是可用 JD。

workflow.py 不执行模型推断或网页抓取；它维护来源、覆盖、引用与机械边界。render_report.py 展示已验证的记录，诊断只完整解释一次，修改链接回原诊断；focused 汇总保留项，full 显示全部处理。全量导出与轻量对话任务分别完成，局部任务无需伪造完整运行数据。

运行目录在用户工作区。独立模块与统一入口的内容效果须按相同输入和预算进行对照评测，代码通过不代表效果优于单项 Skill。
